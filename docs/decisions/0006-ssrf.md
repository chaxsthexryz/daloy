# 0006: SSRF checks inside the socket's DNS lookup

## Context

The HTTP step calls URLs that users write, often with values from trigger data. Without checks it could reach the database, the API's own ports or a cloud metadata service (169.254.169.254) from inside the deployment. Checking a hostname with one DNS lookup and then letting the HTTP client do a second lookup leaves a gap: a DNS server can return a public address the first time and a private one the second time (DNS rebinding).

## Options

1. Resolve the hostname, check the addresses, then call the URL with the IP and set the `Host` header and TLS server name by hand. This works, but every request has to rebuild what the HTTP client already does, and it is easy to get TLS wrong.
2. A library such as `ssrf-req-filter` or `request-filtering-agent`. These wrap an HTTP agent with similar checks. It adds a dependency for about 60 lines of code, and we would still need our own redirect handling.
3. Pass our own `lookup` function to `http.request`. Node calls it for the one DNS lookup it makes for that socket and connects to the address it returns. We check the addresses there, so the checked address and the connected address are the same.

## Decision

Option 3, with `node:net` `BlockList` for the ranges and `new URL()` for parsing. IP literals skip `lookup`, so `checkUrl` checks them before the request. Redirects are followed by hand (at most 3) so each hop goes through the same checks. Requests use `agent: false` so a kept-alive socket cannot be reused without a lookup. The block list, the resolver and the allowed ports are injectable, so tests can use a local server and a fake DNS.

## Consequences

No new dependency. No connection reuse between HTTP steps, which costs a TCP and TLS handshake per call, and that is fine at this volume. The block list is a fixed set of ranges in code, so allowing an internal service means changing code, which is intended. An HTTP proxy configured through environment variables is not used, since the request goes straight to the checked address.
