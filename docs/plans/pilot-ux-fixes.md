# Pilot UX fixes roadmap

Written 25 November 2026 from [docs/pilot-ux-audit-2026-11-25.md](../pilot-ux-audit-2026-11-25.md). Decision and migration numbers are assigned when each phase is claimed so work stays aligned with `main`.

## Scope boundaries

- `Onboarding.tsx`, `onboarding.css`, `lib/onboarding*.ts`, `lib/locale-onboarding.ts`, and `e2e/onboarding.spec.ts` stay untouched until the owner signs off on the onboarding design (`F6` is gated on owner approval).
- Existing architecture remains intact: `#/secrets` already exists from `N26` (needs discoverability from Apps and templates, not rebuilding); managed OAuth lives behind `N24` env config (manual credential panes still need UX and CSS fixes); UniSMS is operator-managed per `U6`/`N7` (needs clear preview-plan/quota preflight messaging rather than exposing credentials in Apps); `Ask about a request` (`N10b`) is reference lookup (needs a request picker and honest copy).
- Never reset the owner's local `pgdata` volume or alter `.impeccable/`.

## Guardrails

- Claim one phase at a time in `PROJECT.md` on `main`, work in a dedicated git worktree and branch (`git worktree add ../daloy-<phase> -b <phase-branch> main`), plan first and wait for the owner's `"go"`.
- Write tests first for non-trivial logic (quota guards, preflight checks, route matching, formatting helpers).
- Verify each phase with `pnpm lint`, `pnpm typecheck`, `pnpm test`, and targeted `pnpm e2e`, then update `docs/how-it-works.md` and `docs/decisions/` where behaviour changes.
- Suggest `/clear` between phases.
