# AI stress test, 23 November 2026

Build with AI was tested the way a seller uses it. Each of the 61 cases in `apps/api/scripts/ai-stress-cases.json` is a chat:

- The first message is the seller's request.
- Any question the AI asks gets the case's next scripted answer, then "Build it now with what you have." (the console's button).
- Edit cases send a change afterwards with the draft attached.

The script calls `chatTurn` in `apps/api/src/ai-chat.ts`, the same code as `POST /ai/chat`, with 6 conversations at a time.

A case passes when it ends in a valid draft with the expected trigger and steps and no checker warnings left. The six unsupported cases (TikTok, Lazada, Viber, a bank password, a weather question, a prompt injection) only need a draft, and the summaries were read by hand.

Model: deepseek-flash, thinking off, JSON object mode, the connection kymavo builds for `api.deepseek.com`.

At DeepSeek's list price ($0.30 per million input tokens and $1.20 per million output, peak, no cache), run 2 cost about $0.22 for all 61 conversations, or about $0.004 each.

## What failed before, and the fixes

- SMS, Messenger, payments, Shopify, Discord, Trello, Notion and Google Docs became http, telegram or webhook steps. The prompt left those steps and triggers out to fit small local models. Hosted models now get them all (decision 0106).
- Three replies were refused as "not a JSON object". The model had closed the object once too often. `extractJson` now tries the earlier `}` characters.
- Questions on complete requests, such as "Where should each order also be recorded?" after "email them a thank-you". The hosted chat prompt now says to draft a complete request at once and to choose small details itself.
- Shopify products from a form looped on the same question for six turns, then failed. Lint refuses form values in a Shopify step, and the model was not told. It now drafts a manual run with example values and says so.
- "Send a Viber message" was summarised as Viber while the step was SMS. The hosted prompt now says to name an app kymavo lacks and what the draft uses instead.

## Still open

- `taglish-cod` ("Kapag COD yung order...") picked the Shopify order trigger in run 2 when the seller did not say Shopify.
- Making Shopify products needs an owner-only input. A manual run has no fields, so the owner edits example values in the step before each run.
- A local Ollama model keeps the short prompt, so it still cannot draft SMS, Messenger or Shopify workflows.
- Results vary from run to run, so compare a change against more than one run.
