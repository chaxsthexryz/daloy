# Live check: Airtable, Notion and Trello OAuth

Status: **unverified**. No real provider request was made for this check. An owner runs this manually with disposable accounts and test data. Record only pass, fail, date and a sanitized observation. Do not record tokens, client secrets, authorization codes, callback query strings, personal data or full provider responses. Provider app registration fees, eligibility and any review required for this deployment are unverified; check the current provider consoles before use.

## Preparation

1. Use an isolated Daloy installation and a workspace manager account. Set a public callback URL and the relevant client ID and secret on the server as described in the installation setup. Register `<PUBLIC_URL>/settings/connections/oauth/callback` at each provider. Restart after changing environment configuration. Do not paste secrets into reports.
2. Prepare an Airtable base and table, a Notion database with a title property, and a Trello board and list, all containing synthetic data. Make a second target in each provider to check target changes. Confirm the provider account is allowed to access these test resources.
3. Configure Airtable for `data.records:write` and `schema.bases:read`. Configure Notion's public integration with read and insert capabilities. Configure Trello as a confidential OAuth 2 client with `read:member:trello`, `read:board:trello` and `write:board:trello`; Daloy requests `offline_access` in the authorization URL. Review the actual permissions on the consent screens. Trello's member scope includes email and memberships.

## Checks

- [ ] Airtable: connect, choose the test base and table, save, and run one synthetic record delivery. Confirm the record appears once in the chosen table. Decline consent on a new attempt and check the existing connection remains usable. Verify an unshared base is absent and an invalid or unlisted target cannot be saved.
- [ ] Notion: connect, share the test database in the consent screen, select it in Daloy and create one synthetic page. Confirm its title is correct. Check a database not shared with the integration is unavailable, and observe how a database newly shared after consent becomes visible. Search visibility and timing are unverified.
- [ ] Trello: connect using the confidential OAuth 2 client, select the test board and list, then create one synthetic card. Confirm it appears once in the list. Check an inaccessible board or unlisted target cannot be saved. Verify the configured scopes and the actual token endpoint against the current provider configuration. Daloy sends no `audience` parameter.
- [ ] For each app, change the target after queuing a test delivery and verify the existing pinned-target review behavior. Reconnect the same account, then a different test account, and check the selected target is appropriate to the new grant. Exercise permission removal and confirm Daloy reports the failure without displaying credentials.
- [ ] Exercise refresh in a controlled test, including a rotated refresh token where the provider issues one. Check that subsequent picker and delivery operations work. Do not reuse a token deliberately against Airtable: its safety rules can revoke the grant. Real refresh lifetimes, race and crash recovery have not been established by this checklist alone.
- [ ] Disconnect each app and confirm Daloy no longer uses its local credential. Check whether provider access remains and revoke it in the provider's account settings when necessary. Notion documents [an access-token revoke endpoint](https://developers.notion.com/reference/revoke-token), which Daloy calls on disconnect; verify the result and whether the provider shows the grant as revoked. The endpoint documentation does not establish what happens to the associated refresh token. This behavior is unverified. Trello OAuth 2 revocation remains unverified; legacy Trello token documentation is not proof of OAuth 2 revocation.
- [ ] Remove the synthetic records, pages and cards and revoke any remaining test grants. Record the date and sanitized results in the release evidence, with failures and untested items explicit.
